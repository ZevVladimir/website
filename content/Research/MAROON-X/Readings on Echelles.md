# Echelle data reduction

![[echelle_data_redux_flow_chart.png.png]]

## Image Preparation

Use CCD to record image from the echelle

1. Generate bias frame
    1. Generated from several raw CCD frames with no light and zero exposure time
    2. Take the median of these frames
2. Generate flat-field frame
    1. Generated from several CCD frames illuminated with a uniform source. Determines relative sensitivity of each pixel
    2. Subtract the median bias frame and a zero-offset constant
    3. Take the median of the resulting frames
3. Subtract bias frame
    1. Subtract the median bias frame from each arc frame (CCD frame taken with an arc lamp to calibrate to known wavelengths) and object frame (CCD frame of an object of interest in the sky)
4. Subtract zero-offset
    1. A selected area of the CCD overscan region (a region of ‘empty’ pixels as read from the detector creating a band around the image)
    2. Take the median of the region (avoid cosmic rays)
    3. Subtract from every pixel in the image
5. Crop images
    1. Remove regions like the overscan or other areas of non-useable data that interferes with the data-reduction engine
6. Rotate and orient images
    1. To fit requirements of the echelle data-reduction package will need to rotate and orient (reflect) in the expected way

## Order Location

Finding the approximate position of each order in the image. Then select which orders to actually use and ignore ones with no useful info

## Order Tracing

Determine the path of each order across the image.

Tracing procedure:

1. Sample each order in steps along the dispersion direction
2. The program will estimate the center of the order at each sample point
3. Then can fit a curve to the data
4. Sometimes points will be ignore like if there are a lot of cosmic rays, the order isn’t very bright, or if there are strong absorption features

## Slit Definition

- Each order of the echelle spectrogram contains an image of the spectrographic slit
- Slit size is determine by the decker
- To determine which pixels are within the slit use the flat-field frame which is set to the maximum size allowed
- After the decker is set in the software inspect the object frame to determine which contribute from the object and if there are any from the sky or local background
- Depending on if there is order-to-order variation then sometime each order will need to be profiled separately

## Flat Fielding

Removes pixel-to-pixel variations in the response of the detector and any interference fringes

- Statistical extraction methods require normalization of the flat field which removes the color of the lamp used
- Normalized fields are generated by fitting a polynomial to the shape of each order along the dispersion direction (sometimes int he spatial direction as well)
- Pixels in any inter-order gaps, where no signal, are set to 1

## Background Handling

- Background consists of
    - Offset from the CCD output processing electronics
        - Removed during CCD data preparation phase
    - Optional pedestal from pre-flashing the CCD to overcome charge transfer inefficeincy at low-signal levels
        - Removed during CCD data preparation phase
    - Thermally generated CCD dark signal
        - Normally small for short (minutes) exposures
    - General scattered light
    - Diffuse light in the inter-order space from adjacent orders
    - Sky background
- Methods to deal with determining background signal level
    - Use the sky pixels as determined in the “Slit Definition”
    - Use a surface fitted to the inter-order background of the whole image
- Shouldn’t fit a single surface to the background of a whole image as it is computationally intensive so use local background unless there is none

## Extraction of Spectra

- Linear approach
    - Integration of all pixels selected in the profiling step with equal weighting
    - Corresponding signal in the background channel is subtracted
    - Benefit: not as computationally demanding and good for checking quickly
    - Con: does not account for the fact that pixels at the edges of the order profile contain smaller part of the signal than those in the middle of the profile and as such have a smaller SNR
- Optimal approach
    - Need to know the readout noise and gain of the CCD camera
    - Requires the spatial profile of the object to be a smooth function of wavelength
        - If spatial (cross-dispersion) resolution is required or the spatial profile varies rapidly with wavelength this approach is not useful
    - Only gives significant improvement at low signal to noise levels
    - The profile models can be used to reject cosmic rays on the object/background channels
- Results in a set of data frames called collapsed echelle spectra

## Wavelength Calibration

For each object or arc CCD have 3 dimensions: order, sample number, and intensity. Want to determine the relationship between wavelength and sample number

- General steps
    - Look at the arc (or comparison) spectrum and try to identify features of known wavelength
    - Fit a low-order polynomial to the arc wavelength-sample relation
    - Paste the wavelength-sample relation from the comparison spectrum to the object spectrum
- Can fit the wavelength-sample relation for each order (1D) or model the whole echellogram (2D)
    - If doing a 2D model use a 1D fit for at least 3-4 orders first
- Ideally each order that is fitted should have at least 3-4 identifiable spectral lines
- After calibrating the the comparison spectrum can copy the wavelength scale onto the object spectra
    - Could be good to calibrate 2 arcs on each side of the object exposure in time to remove any time variation

## Finishing Reduction

- Blaze correction
    - The per-order normalized flat field models can be divided into extracted order spectra to remove the blaze function for the echelle
- Flux calibration
    - An alternative to blaze correction
    - The object and standard star spectra are summed in the same pass bands as in the reference tables. Then calculate the correction factors from the standard star spectrum and the reference tables
- Re-binning Spectra (Scrunching)
    - By having a fixed wavelength scale (can re-bin data into this on a fixed wavelength interval or a fixed velocity interval)
    - Scrunching is like applying a filter to the data
- Combining Orders (Merging)
    - After blaze correction and scrunching
    - Combine the orders into a single spectrum across different exposures

## Handling Cosmic Rays

- Inspection by eye
    - Not as useful for object frames than in dark frames
- Median filtering
    - Apply one filter along rows and another along columns
    - Divided into the original image and get the histogram of the result
    - A clear cut off in the histogram is visible if there are lots of cosmic rays
- Profile modeling
    - Generally part of the optimal extraction
    - Construct profile of the “real” science data you can find statistically unlikely cosmic ray hits can be found even within the spectra
    - Computationally costly
- Comparison of “Identical” Frames
    - When you have several images of the object in the same configuration
    - Can get a median image and any pixels which deviate strongly from the median are likely cosmic rays

Can either interpolate across a cosmic ray hit or just flag it so it isn’t used in the spectrum extraction

- Traditional spectrographs use a diffraction grating or prism to produce a spectra which is captured with a CCD
    - The amount of spectra that is able to be captured is limited by the size of the CCD
    - Much of the detector besides the spectra is unused
- Echelle has rulings that are spread further apart
    - Leads to higher dispersion for a short wavelength range in each order
    - Higher orders overlap
    - To combat this cross-dispersing element (a lower dispersion grating) is used to produce an order separation
- Echelle splits light in two orthogonal directions (2D dispersion) with 2 dispersion stages
    - **Allows for high spectral resolution and large spectral bandpass**
    - No moving parts and compact
